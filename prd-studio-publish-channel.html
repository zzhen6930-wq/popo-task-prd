WorkHub Studio Agent 上架渠道与标签复用

让租户管理员明确决定 Agent 去哪里被使用，让渠道用户清楚识别 Agent 与模板的提供方。
文档版本v1.0状态待评审产品张振关联原型Studio 上架渠道高保真原型更新日期2026-09-21

01背景与目标

1.1 业务背景

租户管理员在 WorkHub Studio 中创建和维护 Agent，但用户最终在个人伙伴或企业伙伴等渠道中发现并使用 Agent。现有「工作伙伴」字段只能表达单一去向，无法清楚说明 Agent 当前上架在哪个消费渠道。

同时，各租户可以维护 Agent 标签。如果缺少统一标签来源，不同租户容易创建含义相同、名称不同的标签，用户在渠道端看到的分类和筛选口径也会逐渐失去一致性。

1.2 用户问题

用户当前问题期望
Studio 租户管理员不清楚 Agent 将在哪个渠道被消费，也无法按明确渠道执行上架和下架。创建 Agent 后，可选择一个目标渠道，并在列表中直接确认当前上架结果。
普通租户管理员需要自行理解和创建标签，容易重复造词。优先复用网易 POPO 提供的官方标签，同时保留添加本租户标签的能力。
伙伴渠道用户无法准确判断 Agent 或模板是谁提供的。清楚看到创建人或模板来源，并区分平台提供内容与个人自建内容。

1.3 产品目标

  1. 将 Studio Agent 的「工作伙伴」能力升级为通用的上架渠道能力。
  2. 支持租户管理员将一个 Agent 上架到个人伙伴或企业伙伴中的一个渠道，并可下架。
  3. 建立「官方标签供全租户复用、租户标签独立维护」的标签体系。
  4. 统一伙伴渠道中的 Agent 创建人和模板来源口径，让用户知道内容由谁提供。
  5. 明确 Studio 与渠道的职责边界：Studio 记录供给数据，渠道决定展示对象与可见范围。

02用户与使用场景

用户角色主要场景用户诉求
网易 POPO 租户管理员维护官方标签新增适用于所有租户的标准标签，减少重复定义。
普通租户管理员管理 Agent、选择渠道、维护标签复用官方标签；按自身业务补充租户标签；决定 Agent 上架到哪个渠道。
个人伙伴用户查看和使用 Agent看到渠道允许自己访问的 Agent，并知道其创建方。
企业伙伴用户查看和使用企业 Agent看到企业范围内可用的 Agent，并知道其创建方。
伙伴模板用户查看模板并创建 Agent知道模板来自哪个 Studio 租户，再决定是否使用。
核心用户故事

作为租户管理员，我希望把 Agent 上架到明确的消费渠道，并能随时确认或撤销上架，以便目标用户在正确渠道中使用它。

作为伙伴渠道用户，我希望看到 Agent 创建人或模板来源，以便判断内容是否可信、是否适合使用。

03产品范围

3.1 本期范围

  • Studio Agent 管理中的字段名称、筛选条件和上架/下架能力。
  • 个人伙伴、企业伙伴两个上架渠道，单个 Agent 同时只能选择一个。
  • 网易 POPO 官方标签的跨租户继承与只读复用。
  • 各租户自有标签的新增、修改和删除。
  • 个人伙伴、企业伙伴的 Agent 创建人展示口径。
  • 伙伴模板页的模板来源展示口径。

3.2 非本期范围

  • 渠道如何计算用户可见范围、排序、推荐和搜索结果。
  • 渠道内 Agent 的会话、任务、技能和使用范围配置能力。
  • 新增个人伙伴、企业伙伴以外的渠道。
  • 将普通租户标签反向共享给其他租户。

04核心业务规则

4.1 上架渠道

规则定义
字段命名Studio Agent 列表原「工作伙伴」统一改为「上架渠道」。
渠道范围本期包含「个人伙伴」和「企业伙伴」。
选择数量单选。一个 Agent 同一时刻只能上架到一个渠道，不存在同时上架两个渠道的情况。
未上架状态新建 Agent 默认未上架，上架渠道为空。
上架结果完成上架后，Studio 记录所选渠道，列表展示该渠道。
下架结果已上架 Agent 可下架；下架时默认选中当前渠道。完成后上架渠道清空。
操作互斥未上架 Agent 仅提供「上架」；已上架 Agent 仅提供「下架」，二者不同时出现。
渠道消费Studio 不主动向渠道推送展示结果。用户进入渠道时，渠道查询 Studio 中符合条件的 Agent。
可见范围Studio 只提供 Agent、渠道、标签等记录；最终向哪些用户展示，由目标渠道按自身规则决定。
产品边界：“已上架”表示目标渠道可以查询到该 Agent，不等同于所有渠道用户都能看到该 Agent。

4.2 标签复用

标签类型创建方其他租户权限适用规则
官方标签网易 POPO 租户可使用，不可修改或删除网易 POPO 新增后，其他租户自动继承；用于鼓励统一表达和跨租户复用。
租户标签当前普通租户不可见、不可使用仅当前租户管理和使用，用于补充官方标签未覆盖的业务语义。
  • Agent 可同时使用官方标签和当前租户标签。
  • Studio 负责记录 Agent 关联的标签值，不定义标签在渠道端的展示位置、样式、筛选方式或可见范围。
  • 渠道按自身产品规则查询并使用标签。

4.3 渠道端来源展示

渠道对象创建方式展示字段展示值
个人伙伴 / 企业伙伴 AgentStudio 创建并上架创建人Studio 所属租户名称，例如「易协作」。
个人伙伴 / 企业伙伴 Agent用户在伙伴页面自行创建创建人创建该 Agent 的用户姓名，例如「张振」。
伙伴模板全部由 Studio 提供模板来源Studio 所属租户名称，例如「易协作」。
“创建人”是面向渠道用户的来源认知字段。Studio 创建的 Agent 不展示 Studio 内部具体操作人，避免用户误认为该 Agent 属于某个个人。

05用户流程

5.1 Agent 上架

1
找到待上架 Agent租户管理员在 Studio Agent 列表确认 Agent 当前未上架。
2
选择上架渠道管理员选择「个人伙伴」或「企业伙伴」中的一个渠道。
3
确认上架系统保存渠道，列表展示该渠道，操作变为「下架」。
4
渠道查询并展示用户进入对应伙伴渠道后，渠道查询 Studio 数据，并按渠道规则判断是否展示。

5.2 Agent 下架

1
发起下架管理员对已上架 Agent 执行下架。
2
确认当前渠道系统默认选中该 Agent 当前唯一的上架渠道。
3
完成下架系统清空上架渠道，列表恢复「上架」操作；渠道后续查询不再返回该 Agent。

5.3 租户使用标签

1
查看可用标签普通租户管理员同时看到网易 POPO 官方标签与本租户标签。
2
优先复用存在合适官方标签时，直接用于 Agent，不重复创建。
3
补充租户标签官方标签无法覆盖业务含义时，管理员新增本租户标签并使用。

08异常与边界

场景产品处理
未选择渠道便确认上架不保存，并提示用户选择一个渠道。
已上架 Agent 再次尝试上架不提供重复上架入口；用户需先下架，再选择新渠道上架。
渠道切换本期不提供直接换渠道；先下架当前渠道，再重新上架目标渠道。
普通租户修改官方标签不允许修改或删除，仅可选择使用。
网易 POPO 删除已被引用的官方标签删除前提示影响范围；删除后的存量 Agent 解除该标签关联，其他配置不受影响。
普通租户创建同名标签同一租户内不允许与可用官方标签或现有租户标签重名，提示优先复用。
Studio 租户名称变更渠道端 Agent 创建人和模板来源应展示最新租户名称。
Agent 下架时用户正在使用下架影响后续发现与新入口；进行中的会话如何处理沿用渠道现有规则。
渠道查询异常渠道不展示无法确认上架状态的 Agent，避免错误曝光。

09验收标准

  1. Studio Agent 列表不再出现「工作伙伴」字段，统一显示「上架渠道」。
  2. 未上架 Agent 显示「上架」操作；已上架 Agent 显示「下架」操作，同一行不同时出现两者。
  3. 上架时个人伙伴、企业伙伴只能选择一个，保存后列表只显示一个渠道。
  4. 下架时默认选中当前渠道，确认后 Agent 变为未上架。
  5. 个人伙伴只能获得上架到个人伙伴的 Agent；企业伙伴只能获得上架到企业伙伴的 Agent。
  6. 普通租户能看到并使用网易 POPO 官方标签，但不能修改或删除。
  7. 普通租户能维护自己的标签，且不会影响网易 POPO 官方标签或其他租户。
  8. Studio 创建并上架的 Agent，在伙伴渠道中将创建人展示为 Studio 租户名称。
  9. 用户在伙伴页面自建的 Agent，将创建人展示为该用户姓名。
  10. 伙伴模板页所有模板均展示 Studio 租户名称作为模板来源。
  11. 渠道端标签展示和用户可见范围不由 Studio 固定，遵循各渠道自身规则。

渠道供给规模个人伙伴/企业伙伴已上架 Agent 数、未上架 Agent 数判断各渠道内容供给是否充足。
