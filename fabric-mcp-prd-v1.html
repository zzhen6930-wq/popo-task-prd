WorkHub · MCP 三角色协同机制

Studio 超管上架分配 → B 端租户配货架并绑定 Agent → C 端按鉴权类型使用。以产品逻辑为主，交互从简。
📅 2026-07-30 🏷️ v3.0 👤 作者：青远（张振） 🧩 归属：WorkHub Studio / 租户后台 · MCP
1概述与三角色分工

MCP（Model Context Protocol）让 Agent 调用外部系统的工具与数据。本机制围绕三个角色协同：超管负责上架 MCP 与分配租户，租户负责配置 MCP（含公共账号、打标分类、绑定 Agent），C 端负责按鉴权类型使用。

① Studio 超管

  • 上架内置 MCP
  • 上架时指定鉴权类型
  • 分配可使用租户
  • 不碰凭据、不做账号授权

② B 端租户后台

  • 内置 MCP 可配公共账号
  • 可自建自定义 MCP
  • 对全部 MCP 打标 / 分类
  • 绑定 Agent 使其生效

③ C 端用户

  • 场景1：自建 Agent（可分享）
  • 场景2：直接用 B 端 Agent
  • 按鉴权类型完成授权
① 上架 MCP ▶ ② 分配租户 ▶ ③ 租户配货架（含打标） ▶ ④ 绑定 Agent ▶ ⑤ C 端按鉴权使用
🔑 一句话定位
超管上架 MCP 并分配租户；租户可配置公共 API Key 并指定 C 端用户使用；C 端用户按照租户配置决定是否需要用自己账号鉴权。

3角色①：Studio 超管 · 上架与分配

3.1 上架内置 MCP

配置项说明
配置方式手动配置 或 导入 json
图标 / 名称 / 备注图标支持上传替换；备注用于说明用途
传输类型SSE / HTTP
服务器 URLMCP 服务端地址
鉴权类型上架时手动指定三选一（POPO 静默 / OAuth 外跳 / 自定义 API），非自动判定
可使用租户全部租户（默认）/ 指定多选；可先上架、后配租户
导入 json 无需 Headers
超管上架不填任何凭据；json 仅含 name / transport / url。凭据由租户或用户在后续环节补。

3.2 鉴权类型与账号鉴权归属

超管不做 MCP 账号授权。提供账号是租户或用户的事。超管只在上架时指定鉴权类型，决定后续由谁、以何种方式提供凭据。

3.3 分配与可见性

  • 可使用租户 = 全部 → 所有租户可见；= 指定 → 仅所选租户可见。
  • 分配后，MCP 进入被授权租户后台「内置 MCP」列表。
4角色②：B 端租户后台 · 配置 MCP

租户后台管理本租户 MCP 货架 = 内置 MCP（可补公共账号）+ 自定义 MCP，并通过绑定 Agent 使其生效。

4.1 内置 MCP

  • 展示超管分配来的 MCP，不可删除、不可改图标、不可改传输参数。
  • OAuth 类与自定义 API 类均可配「公共账号」（Headers）：
    • 配了公共账号 → 全租户用户共用该账号（如租户统一提供的合规检查类 MCP 账号）；
    • 未配公共账号 → 每个用户使用时各自完成账号鉴权 / 配置自己的账号。
  • 公共账号 + 展示标签定向分发：租户在 Studio 内置 MCP 配好 Headers 后，通过展示标签定向分发给指定 C 端用户；这些用户在创建 Agent 时即可见该 MCP，添加后免鉴权直用——鉴权已在 Studio 侧完成（如企查查等对外数据类 MCP）。
  • POPO 静默类无需配凭据，用户以自己 POPO 身份静默授权使用（租户未配置公共账号情况下）。

4.2 自定义 MCP

  • 手动配置或粘贴 json，传输 SSE / HTTP。
  • 可上传图标；Headers 可选（可不填）。
仅 SSE / HTTP
不支持 STDIO；自定义 MCP 只接入 SSE / HTTP 远端服务。

4.3 展示标签与分类

  • 可对本租户下全部 MCP（内置 + 自定义） 打「展示标签」和「分类」。
  • 后台提供打标能力，复用当前展示标签和分类逻辑（与 Skills 一致：官方展示标签 + 分类）。

4.4 绑定 Agent（MCP 生效的唯一途径）

  • MCP 需绑定到 Agent 才可被调用。
  • Agent 是 MCP 的唯一载体——货架上的 MCP 只有进入某个 Agent 才产生实际使用。
🏷 AgentHub 租户特例
AgentHub 无需在 Studio 后台为 Agent 绑定 MCP。Studio 仅向 AgentHub 提供内置 MCP 和自定义 MCP，如何使用由 AgentHub 应用自行决定（定制能力）。
5角色③：C 端用户 · 按鉴权使用

AgentHub 本身也是一个大 B 端租户；其上的 C 端用户有两种使用场景。

5.1 场景 1：自己创建 Agent 绑 MCP（可分享给他人）

鉴权类型创建者本人Agent 分享给他人后租户在 Studio 配公共账号 + 标签分发
POPO 静默 用自己账号静默授权直用 他人也用自己账号静默授权直用（谁用谁授权） 免鉴权直用（鉴权已在 Studio 完成，共用公共账号）
OAuth 外跳 创建时点「链接」外跳授权，可跳过；跳过后在 Agent 执行任务发现未授权时，弹 MCP 授权卡片外跳授权 谁用谁授权：他人只能在执行任务时通过授权卡片外跳授权，无公共账号 免鉴权直用（鉴权已在 Studio 完成，共用公共账号）
自定义 API 创建时点「链接」出配置弹窗输 api key，可跳过；跳过后执行任务未授权时，弹卡片输 api key 授权 谁用谁授权：他人只能在执行任务时通过卡片输自己的 api key，无公共账号 免鉴权直用（鉴权已在 Studio 完成，共用公共账号）

免鉴权分发路径：租户在 Studio 内置 MCP 配好 Headers 并用展示标签分发后，被分发的 C 端用户在创建 Agent 时可见该 MCP，添加即免鉴权直用，无需以自己账号授权。

5.2 场景 2：直接使用 B 端已创建好的 Agent

鉴权类型B 端配了公共账号（Headers）B 端未配
POPO 静默免鉴权直用（鉴权已在 Studio 完成，共用公共账号）用自己账号静默授权直用
OAuth 外跳免鉴权直用（鉴权已在 Studio 完成，共用公共账号）C 端自己外跳授权
自定义 API免鉴权直用（鉴权已在 Studio 完成，共用公共账号）C 端自己手动输 api key

未配公共账号时，C 端自行授权的逻辑与场景 1 一致，只是发生在使用 B 端 Agent 时。

6三条关键产品边界
① 公共账号（免 C 端鉴权）有两条来源：(a) 租户在 Studio 内置 MCP 配 Headers + 展示标签定向分发 → 指定 C 端创建 Agent 时可见并免鉴权直用（鉴权已在 Studio 完成）；(b) B 端为其已建 Agent 配 Headers → C 端直接用该 Agent 免鉴权。除此之外，C 端自建 Agent 分享一律「谁用谁授权」，不存在公共账号。
② MCP 启停 = 是否绑定 Agent。 租户后台不设独立停用开关；未绑 Agent 的 MCP 天然不可用。
③ 授权时机双通道。 创建时「链接」可授权也可跳过；跳过后在 Agent 执行任务时 通过授权卡片补授权（OAuth 外跳 / 输 api key）。POPO 静默类始终以用户自己账号静默授权。
7范围与非目标

✅ 本期做

  • 超管：上架内置 MCP（手动/json + 图标）、上架选鉴权类型、分配租户
  • 租户：内置补公共账号、自建自定义 MCP、全部 MCP 打标分类、绑定 Agent
  • C 端：两场景 × 三鉴权类型的授权逻辑（含授权卡片补授权）
  • AgentHub 租户特例

🚫 本期不做

  • STDIO 传输
  • 租户侧独立启停开关（以绑定 Agent 替代）
  • C 端自建 Agent 的公共账号共享
  • MCP 连通性健康监控、工具级细粒度权限
8验收标准（产品逻辑）
  1. 超管可上架内置 MCP（手动/json + 图标），传输仅 SSE/HTTP，上架时手动选鉴权类型，json 无 Headers；可分配全部/指定租户，支持先上架后配。
  2. 超管不出现任何账号授权入口。
  3. 租户后台内置 MCP 不可删/不可改图标/传输；OAuth 与自定义 API 类均可配公共账号，配/不配对应全租户共用 / 用户各自授权；POPO 静默类以用户自己账号静默授权。
  4. 租户可自建自定义 MCP（SSE/HTTP，Headers 可选，可传图标）。
  5. 租户可对全部 MCP 打展示标签与分类，复用现有 Skills 标签/分类逻辑。
  6. MCP 必须绑定 Agent 才生效，未绑定视为停用，无独立开关。
  7. C 端场景1：静默直用；OAuth/API 类创建时可授权可跳过，跳过后执行时授权卡片补授权；分享他人一律谁用谁授权，无公共账号；但若租户在 Studio 配 Headers + 标签分发给该用户，则创建 Agent 时免鉴权直用。
  8. C 端场景2：B 端配了公共账号则直用，未配则自行授权。
  9. AgentHub 特例：Studio 提供内置+自定义 MCP，不在 Studio 绑定 Agent，使用由 AgentHub 定制。
