WorkHub · MCP 两层管理机制

重构 MCP 管理为「Studio 超管上架分配 → 租户后台补凭据 → Agent 绑定 → C 端使用」四段式两层管理链路。
📅 2026-07-24 🏷️ v2.0 👤 作者：青远（张振） 🧩 归属：WorkHub Studio / 租户后台 · MCP
1背景与目标

MCP 需要在平台超管与租户两个层级分别管理：超管负责上架内置 MCP 并决定分配给哪些租户；租户负责补充自己的凭据、接入自建 MCP。本期把 MCP 拆成清晰的两层，并串起「上架 → 分配 → 补凭据 → 绑定 → 使用」全链路。

① Studio 超管平台（本 PRD + 原型）

  • 左侧新增「MCP 管理」菜单
  • 上架内置 MCP，导入 json（sse / http），上架时指定鉴权类型
  • 配置可使用租户（默认全部 / 指定多选）

② 租户后台（本 PRD + 原型）

  • 左侧「MCP」菜单，分内置 MCP / 自定义 MCP 两 Tab
  • 内置 MCP：只能补 Headers（补了共用租户账号，不补则用户各自配）
  • 自定义 MCP：手动配置 / 粘贴 json，sse / http，Headers 可不填
🔑 一句话定位
超管上架并分配货架，租户补凭据并自建补充，Agent 侧绑定，C 端按鉴权类型使用。三类鉴权（POPO 静默 / OAuth 外跳 / 自定义 API）在超管上架时指定，贯穿全链路。
2核心概念与术语
术语说明
MCPModel Context Protocol，让 Agent / 模型链接外部系统工具与数据的标准协议
内置 MCP由 Studio 超管上架、并分配给租户的 MCP；租户不可删除，仅可补 Headers
自定义 MCP租户后台自建接入的 MCP，支持手动配置或粘贴 json
传输类型本模型仅支持 SSE（服务端推送）/ HTTP（HTTP 流）两种；STDIO 已弃用
鉴权类型POPO 静默（无需连接）/ OAuth 外跳（点「链接」跳浏览器授权）/ 自定义 API（用户或租户配 Headers）；上架时指定
Headers即 api key 凭据。租户补 Headers → 全租户共用租户账号；不补 → 每个 C 端用户各自配
3Studio 超管平台 · MCP 上架与分配

在超管左侧新增「MCP 管理」菜单，卡片陈列已上架的内置 MCP。右上角「＋ 添加 MCP」上架新 MCP。

3.1 添加 MCP 弹窗

字段说明
配置方式手动配置 或 导入 json 二选一
服务器名称 / 备注MCP 名称与用途说明
传输类型SSE / HTTP 二选一
服务器 URLMCP 服务端地址
鉴权类型（上架时指定）三选一：POPO 静默 / OAuth 外跳 / 自定义 API。由管理员上架时手动选择，非自动判定
可使用租户全部租户（默认） 或 指定租户（多选）
导入 json 无需 Headers
上架时导入的 json 不含 Headers——凭据由各租户 / 用户在后续环节补充，超管不持有终端凭据。

3.2 OAuth 类 MCP 的「链接」

鉴权类型为 OAuth 外跳 的 MCP，卡片上出现「🔗 链接」入口；点击跳浏览器完成应用级 OAuth 授权，授权后标记「已授权」。POPO 静默类无需连接；自定义 API 类的凭据在租户 / 用户侧补。

3.3 分配与可见性

  • 上架并分配后，MCP 在被分配租户的租户后台「内置 MCP」Tab 中可见。
  • 可使用租户 = 全部 → 所有租户可见；= 指定 → 仅所选租户可见。
4租户后台 · MCP 管理

租户后台左侧「MCP」菜单，分两个 Tab：

4.1 内置 MCP（超管分配来）

  • 展示超管上架并分配给本租户的 MCP，不可删除、不可改传输参数。
  • 卡片标注鉴权类型徽标（POPO 静默 / OAuth / 自定义 API）。
  • 仅「自定义 API」类可补 Headers：
    • 补了 Headers → 全租户用户共用租户账号；
    • 不补 Headers → 每个 C 端用户使用时各自配置自己的凭据。
  • POPO 静默类开箱即用；OAuth 类由用户使用时点「链接」外跳授权，无需租户补凭据。

4.2 自定义 MCP（租户自建）

字段说明
配置方式手动配置 或 粘贴 json
服务器名称 / 备注MCP 名称与用途
传输类型SSE / HTTP
服务器 URL自建 MCP 服务端地址
Headers（可选）可不填；填则作为该 MCP 的凭据
仅 SSE / HTTP
新模型不再支持 STDIO。租户自定义 MCP 只支持 SSE / HTTP 远端服务。
5Agent 绑定 MCP（逻辑说明 · 不上原型）
场景绑定方式
B 端租户 Agent在 Agent 配置页勾选绑定本租户可见的 MCP（内置 + 自定义）
WorkHub 应用应用自行获取所需 MCP，无需人工在配置页勾选
6C 端使用 MCP（逻辑说明 · 不上原型）

6.1 AgentHub 创建 Agent

用户在 AgentHub 创建 Agent 绑定 MCP 时，按鉴权类型区分：

鉴权类型用户操作
POPO 静默直接可用，无需操作
OAuth 外跳点「链接」跳浏览器完成授权
自定义 API填写自己的凭据（若租户未在后台补 Headers）

鉴权类型使用方式

OAuth 外跳 / 自定义 API需进 AgentHub 完成授权 / 配置后方可使用
7全链路总览
① 超管上架 导入 json（sse/http）+ 选鉴权类型（popo/oauth/api）+ 选可使用租户 │ ② 分配到租户 内置 MCP 出现在被分配租户后台「内置 MCP」Tab │ ③ 租户补凭据 自定义 API 类：补 Headers=共用租户账号 / 不补=用户各自配 │ 并可自建「自定义 MCP」(sse/http, Headers 可选) │ ④ Agent 绑定 B 端 Agent 配置页勾选 / WorkHub 应用自获取 │ ⑤ C 端使用 popo 静默直接用 · oauth 点「链接」外跳 · 自定义 api 填凭据

9验收标准
  1. 超管左侧有「MCP 管理」菜单，卡片陈列已上架 MCP，右上角「＋ 添加 MCP」。
  2. 添加 MCP 弹窗支持手动配置 / 导入 json，传输仅 SSE / HTTP，上架时手动选鉴权类型（popo/oauth/api），导入 json 无需 Headers。
  3. 可使用租户支持全部（默认）/ 指定多选；分配后在被分配租户后台可见。
  4. OAuth 类 MCP 卡片出现「🔗 链接」，点击外跳授权后标「已授权」。
  5. 租户后台「MCP」分内置 / 自定义 两 Tab。
  6. 内置 MCP 不可删除、不可改传输参数；仅自定义 API 类可补 Headers，补/不补对应共用租户账号 / 用户各自配。
  7. 自定义 MCP 支持手动配置或粘贴 json，传输 SSE / HTTP，Headers 可不填，可编辑。
  8. PRD 明确 Agent 绑定（B 端勾选 / WorkHub 自获取）与 C 端使用（静默直用 / OAuth 外跳 / 自定义配凭据）逻辑。
