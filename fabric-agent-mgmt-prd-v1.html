WorkHub Studio · Agent 管理能力增强

在一个 Agents 列表中统一管理「自建 Agent（AgentHub / Workhub Studio）」与「外部连接的智能体（Claude Code / Hermes / OpenClaw / Codex 等）」；详情页由单一配置升级为四 Tab，补齐「使用」（分发管控）与「用量」（成本与用量可视）两大管理维度。
📅 2026-08-05 🏷️ v1.1 👤 作者：青远（张振） 🧩 归属：WorkHub Studio · Agents 模块
1背景与目标

平台在同一 Agents 列表 中承载两类智能体：自建 Agent（AgentHub / Workhub Studio）与外部连接的智能体（Claude Code / Hermes / OpenClaw / Codex 等三方接入）。当前二者缺少统一管理入口与管理维度：无来源区分、详情页只有能力配置，管理员看不到「谁能用、成本从谁扣」。

本次目标：一个列表统管两类 Agent，并在详情页补齐使用范围（分发管控）与用量统计（成本可视）两大管理维度。

🔑 定位
「配置」管能力、「使用」管分发、「用量」管成本与用量，构成 Agent 完整管理视图。具体交互详见原型。
2Agent 列表页

自建与外部连接 Agent 同列表管理，可按名称 / 创建人搜索、按来源筛选；点击行进入详情。列表字段：名称、模型、来源、记忆、状态、创建人 / 时间、更新人 / 时间、操作（编辑 / 删除）。

来源分三类

  • AgentHub、Workhub Studio：自建 Agent。
  • 外部连接的智能体：三方接入，来源列展示具体三方名（Claude Code / Hermes / OpenClaw / Codex 等）。
3外部连接的智能体

三方智能体的角色、技能、工具由三方侧维护，平台可见 / 可管理的信息有限，故做差异化：

  • 列表：模型、记忆显 -；来源显具体三方名。
  • 详情：隐藏「配置 / 记忆」Tab；使用与自建一致；用量仅保留用量概览与变化趋势，隐藏「Token 扣除规则 / 用户用量明细」（扣费逻辑对三方不适用）。
4详情页布局（Tab 化）

详情页由单一配置改为 4 个 Tab：配置、记忆（已有逻辑，仅归位）+ 使用、用量（本次新增）。外部连接智能体隐藏「配置 / 记忆」。

5使用（新增）

后台管理视角，管理员在 Agent 维度管理「谁能用」与「在各群怎么回复」。

5.1 可使用范围

  • 仅自己：仅拥有者可搜索、私聊、使用；加入群聊后群成员可在群内对话。
  • 指定成员或部门：范围内成员可搜索、私聊、使用并加入群聊。范围通过「选择人员」选择部门或人员（交互详见原型）。

5.2 已加入的群聊

列出该 Agent 所在全部群聊，管理员可按群设置回复方式：智能回复（自主判断是否应答）/ 仅 @ 时回复。会话上下文与其他私聊、群聊隔离（只读）。

边界
本 Tab 只做已入群的查看与回复方式治理，不提供拉 Agent 进群入口；进新群需前往目标群设置。
6用量（新增）

在 Agent 维度呈现该 Agent 的用量与成本：总量指标、按应用场景的分布与趋势、Token 扣除规则及按用户明细。所有数据按顶部所选时间范围统计。外部连接的智能体仅展示 6.2 用量概览与 6.3 变化趋势，隐藏 6.4~6.5。

6.1 时间范围

提供 近 7 天 / 本月 / 自定义 三种范围，默认近 7 天；概览、趋势、明细均随范围联动。范围标签统一以起止日期表达（如 7/23 - 7/29）。

6.2 用量概览

四项核心指标，每项均给出总量、按应用场景拆解与环比：

指标口径定义
总 Token 用量智能体使用过程中消耗的 Token 总量。
总会话数用户与该智能体发起的会话总数（非消息数）。
总消息数智能体成功回复的消息总数，每回复一条计 1。
总用户数与智能体对话过的去重用户总数。
  • 应用场景拆解：每个指标的总量向下拆到 4 个应用场景 —— Workhub POPO-单聊 POPO-群聊 SDK，展示各场景数值与占该指标总量的占比，用于观察用量的场景分布。
  • 环比：与上一等长周期对比，同时给出绝对值变化（增减数量）与百分比（增幅 / 降幅），持平记为 0。

6.3 变化趋势

四项指标各对应一张趋势图（Token 用量 / 会话数 / 消息数 / 用户数），用于观察总量与各场景随时间的变化：

  • 多场景对比：每张图同时展示总量与 4 个应用场景共 5 条线，各场景可单独勾选显隐。
  • 粒度切换：支持 日 / 周 / 月 三种横轴颗粒度，对同一时间范围内的数据按日 / 周 / 月聚合，便于不同跨度下的趋势观察。
  • 横轴时间随所选时间范围联动。

6.4 Token 扣除规则

规则决定该 Agent 产生的 Token 从谁的额度扣，二选一，可查看可修改（切换即时生效、不追溯历史）：

  • 统一从我的额度扣除：无论谁使用，都从 Agent 创建者配置的额度统一扣除。该规则下具体扣谁的额度，随 Agent 来源不同而不同（见下表）。
  • 从提问人的额度扣除：谁发起对话就扣谁的额度。不区分来源，AgentHub 与 Workhub Studio 一致，均从提问人的个人积分扣除。
扣除规则来源 = AgentHub（用户创建）来源 = Workhub Studio（租户创建）
统一从我的额度扣除 统一从该个人用户的积分扣除。 统一从该租户的账号扣除。
从提问人的额度扣除 均从提问人的个人积分扣除（两种来源一致）。
说明
「统一从我的额度扣除」文案相同，但因 Agent 来源不同，扣除主体不同：AgentHub 扣创建者个人积分，Workhub Studio 扣租户账号。

6.5 用户用量明细

与扣除规则合并为一个模块，按用户拆分展示各自 Token 消耗、会话数、消息数、应用场景（该用户涉及的场景以标签展示）、占比与扣除归属，用于识别高消耗用户与核对扣费对象。

  • 扣除归属随扣除规则变化，直接显示实际扣费人名：统一从我的额度扣除 → 归属 Agent 拥有者；从提问人的额度扣除 → 归属 各用户本人。
  • 默认按 Token 消耗降序，分页展示，每页最多 10 条。
7范围与非目标

✅ 本期做

  • Agent 列表页统一管理两类 Agent，补齐来源、操作列，支持搜索与来源筛选。
  • Agent 详情页 4 Tab（配置 / 记忆 / 使用 / 用量）。
  • 使用：可使用范围（仅自己 / 指定成员或部门）+ 已加入群聊回复方式。
  • 用量：概览（4 指标 + 场景拆解 + 环比）、变化趋势（多场景 + 日/周/月粒度）、扣除规则（可改）、按用户明细（分页）。
  • 外部连接智能体差异化：列表模型 / 记忆显 -；详情隐藏配置 / 记忆，用量仅保留概览与趋势。

🚫 本期不做

  • 不改动「配置」「记忆」既有逻辑，仅做布局归位。
  • 「已加入的群聊」不提供拉 Agent 进群入口。
  • 扣除规则切换不追溯历史消耗。
  • 不新增账号来源（组织 / 个人）的区分维度。
