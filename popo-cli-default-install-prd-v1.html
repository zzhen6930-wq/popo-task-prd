1背景与目标

1.1 背景

POPO-CLI 已具备 IM、云文档、在线表格、多维表、日程会议室、任务、KM 知识问答、易协作等能力，可供本地 AI Agent 调用完成 POPO 内的办公操作。但目前用户需要主动了解并手动安装，存在两个问题：

  • 认知门槛高：多数员工不知道 POPO-CLI 是什么、能做什么
  • 安装成本高：需自行阅读文档、找到 Agent 配置路径、执行安装与授权

1.2 目标

  • 对已具备 Agent 环境的用户，由客户端默认完成安装，将上手成本降为「一次授权」
  • 对暂无 Agent 环境的用户，通过卡片完成一次性认知触达，并提供自助安装入口
  • 全流程每台设备只打扰一次，不做多轮触达、不做管理后台
💡 一句话需求
客户端检测到已支持的 Agent 就默认装好 POPO-CLI，然后由机器人推一张卡片告诉用户「这是什么、能干什么、点一下授权就能用」；没有 Agent 的用户，推一张介绍卡片引导自助安装，不装也不再打扰。

3整体流程
① 检测本地环境

按设备检测：是否未安装 POPO-CLI、账号类型是否在范围内、是否存在已支持的 Agent

→
② 默认安装 CLI

三项全满足则默认安装 POPO-CLI；不满足则不安装

→
③ 机器人推送卡片

按设备推送并标注设备号：安装后推授权卡片，未安装推自助安装卡片

→
④ 用户授权 / 自助安装

卡片按钮触发登录+授权，或跳转 KM 文章自助安装

分支 A：本地存在已支持的 Agent
  • 客户端默认安装 POPO-CLI，无需用户交互
  • 安装成功后推送已接入卡片
  • 卡片主按钮「授权」，触发 Open ID 登录 + 授权
  • 授权完成后即可在 Agent 中使用
分支 B：本地不存在已支持的 Agent
  • 不执行默认安装
  • 推送能力介绍卡片，说明 POPO-CLI 是什么、支持哪些能力
  • 卡片主按钮「查看安装方法」，跳转 KM 文章
  • 用户不安装则不再触达，流程终止
4本地环境检测P0

4.1 检测时机

规则项说明
触发时机POPO 客户端登录成功时、断线重连成功时
检测维度按设备维度检测，同一账号下的不同设备各自独立判定
检测频次同一设备每天最多检测一次，当日已检测过则跳过
终止条件该设备已推送过卡片后，该设备不再执行任何检测
⚠ 注意
「已推送过卡片」为设备级终止开关：无论用户是否授权、是否自助安装，该设备均不再重复检测与推送。标记需服务端按「账号 + 设备号」持久化，设备之间互不影响。

4.2 检测事项

序号检测项判定条件
①是否已安装 POPO-CLI本机未安装 POPO-CLI（不包括已卸载：曾安装后卸载的设备视为已覆盖，不再纳入）
②账号类型为正式内部员工账号；外部账号、GRP 账号不检测、不安装
③是否存在已支持的 Agent本机存在至少一个受支持的 Agent 工具配置
💡 关于「已卸载」
检测项 ① 判定的是「从未安装过」。用户曾安装后又卸载 POPO-CLI，视为已认知该能力，不重新纳入默认安装与推送范围；需服务端记录该设备的历史安装标记。

4.3 检测后处理逻辑

判定结果默认安装卡片推送说明
不满足 ① 或 不满足 ②不安装不推送直接终止流程，不进入后续判定
① ② ③ 全部满足触发安装推送授权卡片分支 A，卡片主按钮「授权」
满足 ① ②，不满足 ③不安装推送自助安装卡片分支 B，卡片主按钮「查看安装方法」

5默认安装规则P0
规则项说明
安装条件未安装 POPO-CLI（不含已卸载）、账号为正式内部员工账号 且 本机存在至少一个已支持的 Agent 工具
安装维度按设备执行，同一账号下不同设备各自独立判定与安装
安装范围为检测到的全部已支持 Agent 完成安装写入
用户交互无。安装过程静默执行，不弹窗、不阻塞客户端使用
不满足条件不执行安装，进入分支 B 推送流程
安装失败不推送已接入卡片，当日不再重试，次日按检测频次重新判定
⚠ 体验红线
卡片文案不得出现「已检测到你本机的 XX 工具」「已自动为你安装」等表述，避免用户产生「客户端在操控我的电脑」的负面感受。卡片以「POPO 能力已接入你的 AI Agent」的能力视角表达。
6卡片推送规则P0
规则项说明
推送渠道POPO-CLI 小助手机器人，单聊推送
推送维度按设备维度推送。同一账号下每台满足条件的设备各推一张卡片，卡片上展示对应的设备号（POPO 客户端登录设备号）
推送次数每台设备仅推送一次，推送后该设备不再检测
分支 A 时机该设备默认安装成功后推送「已接入卡片」
分支 B 时机该设备检测判定不满足安装条件后，推送「能力介绍卡片」
已安装设备已安装（或曾安装后卸载）POPO-CLI 的设备不推送
用户无响应不做二次触达、不做提醒，流程自然终止

6.1 多设备推送示例

场景推送数量卡片内容
用户 A 有 2 台设备：
01 已安装 CLI，02 满足推送条件		1 张卡片显示 02 设备号
用户 A 有 2 台设备：
01、02 均满足推送条件		2 张卡片 1 显示 01 设备号
卡片 2 显示 02 设备号
💡 为什么按设备推送
POPO-CLI 安装在本地电脑，不同设备的 Agent 环境与安装状态互相独立。按设备推送并标注设备号，用户才能明确「这张卡片对应哪台电脑」，避免在 A 电脑收到卡片却以为 B 电脑已可用。
⚠ 设备号展示要求
设备号取 POPO 客户端登录设备标识，展示为用户可辨认的形式（如设备名 / 设备号），不展示内部 UUID。多张卡片在同一会话内按推送时间先后排列。

8授权流程P0
  1. 用户点击卡片「授权」按钮
  2. 客户端拉起浏览器，打开 Open ID 登录页
  3. 用户完成 POPO 账号登录并确认授权范围
  4. 授权成功后回调客户端，卡片按钮态更新为「✓ 已授权」，提示文案更新为「已完成登录授权，现在可以在 Agent 中直接使用 POPO-CLI 能力」
💡 设计考量
将授权前置到卡片阅读环节，用户一次性完成认知与授权；避免拆成「看卡片」与「首次调用时再登录」两次动作。
状态按钮表现提示文案
未授权蓝色主按钮「授权」完成授权后即可使用 POPO-CLI 能力。
授权中置灰「正在打开 Open ID 登录…」保持不变
已授权绿色「✓ 已授权」，不可再次点击已完成登录授权，现在可以在 Agent 中直接使用 POPO-CLI 能力。
授权失败/取消恢复为「授权」可点击态保持不变，可重新发起

8.1 端能力差异

POPO-CLI 仅能安装到本地电脑，因此授权动作只允许在桌面端完成。

端授权按钮交互说明
桌面端（Windows / macOS）可点击点击后拉起浏览器完成 Open ID 登录与授权
移动端（iOS / Android）可点击但不执行授权点击后弹出提示，引导用户前往电脑端操作
📱 移动端点击提示文案
请在电脑端完成授权
  • 提示形式：轻提示（Toast）或确认弹窗，仅「我知道了」单一按钮，不提供继续授权入口
  • 移动端点击不消耗授权状态，用户在电脑端仍可正常完成授权
  • 卡片在移动端正常展示全部内容（能力清单、使用方法），仅授权动作受限
9自助安装引导P1

分支 B 用户点击「查看安装方法」后跳转 KM 文章，文章需覆盖两条路径：

路径说明
方式一 · Agent 自助安装用户复制固定指令发送给自己的 Agent，由 Agent 完成安装：
参考 https://popo.update.netease.com/popo-cli-installation-guide.md 帮我安装 popo-cli 到当前的 Agent 环境
方式二 · 手动安装到指定路径下载安装包，按文章说明安装到目标 Agent 的配置目录

两种方式安装完成后，均自动弹出 Open ID 登录页完成授权，授权成功后 POPO-CLI 可用。

⚠ 边界
分支 B 用户若始终未安装，不做任何追加触达。若其后续自行完成安装并授权，走 POPO-CLI 既有的安全提示逻辑，不再复用本方案卡片。
10异常与边界
场景处理方式
外部账号 / GRP 账号不检测、不安装、不推送
本机已安装 POPO-CLI不检测、不安装、不推送
曾安装后卸载 POPO-CLI视为已覆盖，不重新纳入：不安装、不推送
默认安装执行失败不推送卡片，当日不再重试，次日重新判定
安装成功但推送失败不标记该设备「已推送」，次日重新推送（仍受每设备一次约束）
用户未点击授权不追加提醒；用户首次调用 POPO-CLI 时按既有逻辑拉起授权
用户多设备登录按设备维度检测、安装与推送：几台设备满足条件就推几张卡片，每张卡片标注对应设备号
用户卸载 Agent 或 CLI本期不做卸载后重推，不回收卡片
移动端点击「授权」不执行授权，弹提示引导用户前往电脑端完成授权
检测过程耗时较长后台异步执行，不阻塞客户端启动与使用
