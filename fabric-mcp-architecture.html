1Studio 超管上架内置 MCP · 定鉴权类型 · 分配租户｜不碰凭据、不做链接

① 上架内置 MCP

  • 配置方式：手动 / 导入 json
  • 传输：SSE / HTTP（无 STDIO）
  • 上传图标 · 名称 · 备注
  • json 无需 Headers
→

② 指定鉴权类型

  • POPO 静默 用户自己账号静默授权
  • OAuth 外跳 授权链接
  • 自定义 API Headers
  • 上架时手动选，非自动判定
→

③ 分配可使用租户

  • 全部租户（默认）/ 指定多选
  • 可先上架、后配租户
  • 分配后进对应租户货架
🔒 超管边界：只上架 + 分配，不持有任何终端凭据；链接 / 授权是租户或用户的事。
▼ 分配到被授权租户
2B 端租户后台配公共账号 · 自定义 MCP · 打标分类 · 绑定 Agent｜AgentHub 也是一个大租户

③a 内置 MCP

  • 可配 Headers（公共账号）
  • 配了 → 全租户共用账号
  • 不配 → 用户各自链接自己账号
  • 不可改图标 / 传输参数
＋

③b 自定义 MCP

  • 手动配置 / 粘贴 json
  • 传输 SSE / HTTP
  • 必传图标 · Headers 可选
＋

③c 展示标签 + 分类

  • 对全部 MCP 打标（同 Skills）
  • 官方「展示标签」+「分类」
  • 后台只提供打标能力
  • 展示策略由前端应用定制
→

④ 绑定到 Agent

  • MCP 靠绑 Agent 生效
  • 不绑定 = 停用（无独立开关）
  • Agent 是 MCP 的唯一载体
📦 货架 = 内置（可补公共账号）+ 自定义；启停不设开关——是否绑定 Agent 即决定该 MCP 是否可用。
▼ Agent 携带已绑定 MCP 交付 C 端
3C 端用户场景1 自建 Agent（可分享）· 场景2 直接用 B 端 Agent

场景 1 · 自己创建 Agent 绑 MCP（可分享给他人）

  1. 静默类：用自己账号静默授权直用；分享后他人也用自己账号静默授权直用。
  2. OAuth 类：建时点「链接」外跳授权，可跳过；执行时未授权 → 弹授权卡片外跳。
  3. 自定义 API 类：建时点「链接」出弹窗输 api key，可跳过；执行时未授权 → 弹卡片输 key。
  4. 分享给他人：OAuth / API 类一律 谁用谁授权（执行时授权卡片），无公共账号。

场景 2 · 直接使用 B 端已建好的 Agent

  1. Agent 由 B 端租户创建并已绑定 MCP。
  2. B 端配了 Headers（公共账号） → C 端无需授权直接用。
  3. B 端未配 → C 端自己授权：OAuth 外跳 / 输 api key。
  4. 授权逻辑同场景1，只是发生在使用 B 端 Agent 时。

⑤ C 端使用鉴权矩阵

鉴权类型 自建 Agent · 创建者 自建 Agent · 分享他人 用 B 端 Agent（B 配了公共账号） 用 B 端 Agent（B 未配）
POPO 静默 用自己账号静默授权直用 用自己账号静默授权直用 用自己账号静默授权直用（无公共账号概念）
OAuth 外跳 建时「链接」外跳，可跳过；执行时弹卡片授权 谁用谁授权：执行时授权卡片外跳 无需授权直接用（共用公共账号） 自己外跳授权
自定义 API 建时「链接」出弹窗输 key，可跳过；执行时弹卡片输 key 谁用谁授权：执行时输自己 key 无需授权直接用（共用公共账号） 自己手动输 api key

🎯 三条关键边界（最容易搞混）

① 公共账号只在「B 端为其 Agent 配了 Headers」时存在。 C 端自建 Agent 分享一律「谁用谁授权」，不存在公共账号。
② MCP 启停 = 是否绑定 Agent。 租户后台不设独立停用开关；未绑 Agent 的 MCP 天然不可用。
③ 授权时机双通道。 创建时「链接」可授权也可跳过；跳过后在 Agent 执行任务时 通过授权卡片补授权（外跳 / 输 key）。
