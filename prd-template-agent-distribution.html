Workhub Studio 模板中心与 Agent 分发

以易协作场景为首个落地对象，建立「母版 → 实例模板 → 实例 Agent」的标准化分发链路

01背景与目标

1.1 业务背景

易协作是网易内部的项目协作平台，其组织形态为「实例 → 项目 → 用户」三层结构：一个易协作实例对应一个业务方（如 H72、大话西游），实例下有多个项目，项目下有管理员与普通成员。

易协作希望为每个项目提供一个 PM 助理 Agent，帮助项目成员完成周报汇总、进度问答、文档生成等工作。这带来两个诉求：

  • 规模化交付——实例数量随业务扩张持续增长，逐个手工创建 Agent 不可持续；
  • 统一管控——所有项目 Agent 的提示词、模型、工具、Skills、MCP 需由平台方统一定义与升级，不能各自漂移。

1.2 现状问题

问题说明
模板能力错位模板此前在超管后台维护，租户无法自主定义面向自己业务的模板，平台方成为交付瓶颈。
无法批量分发缺少将一个模板按业务实例快速铺开的机制，新实例接入需人工重复配置。
缺少归属与可见性Agent 没有业务归属信息，Agenthub 无法判断某个用户应当看到哪些 Agent、能否修改。
配置无法统一升级母版提示词或工具变更后，已交付的 Agent 无法批量同步，长期形成版本分裂。

1.3 产品目标

  1. 将模板管理下沉到租户后台，由租户自主维护面向 Agenthub 用户的模板资产（替换原超管后台模板管理）。
  2. 建立母版 → 实例模板 → 实例 Agent 的三级派生链路，支持易协作通过接口自动化完成初始化与增量接入。
  3. 沉淀实例—项目—成员关系数据，为 Agenthub 提供可见性与权限判定依据。
  4. 通过上架 Agenthub 机制，让业务 PM 能直接使用 Agent 或基于模板自建 Agent。
  5. 母版配置变更可强联动下发到全部实例模板与实例 Agent，保证配置一致性与可审计。

1.4 成功指标

指标目标值口径
实例接入自动化率≥ 95%通过接口生成的实例模板数 / 实例模板总数
新实例接入时长≤ 5 分钟易协作发起调用 → 实例 Agent 可用
母版下发成功率≥ 99%母版变更后同步成功的实例数 / 应同步实例数
Agent 使用覆盖率首期 ≥ 60%产生过会话的实例 Agent 数 / 已上架实例 Agent 数

03核心概念与数据模型

3.1 对象定义

对象归属定义
母版
PM Agent 模板		Studio 租户 租户手工创建的标准模板，是一切实例的配置来源。包含名称、描述、系统提示词、模型、内置工具、Skills 绑定、MCP 绑定（含 brainmaker 知识库）。母版是唯一的配置真源。
实例模板Studio 租户 由母版按易协作实例派生。本质是在母版基础上打上实例标签，全部配置继承自母版且保持联动，仅展示标签（实例标识）为自身独有。与易协作实例 1:1。
实例 AgentStudio 租户 由实例模板生成的 Agent，与实例模板 1:1。本质是在 Agent 上打了实例标签，归属 Studio 租户，在 Agent 管理下统一维护。
项目 AgentAgenthub 用户在 Agenthub 中实际交互的对象，由实例 Agent 初始化而来。项目管理员可在允许范围内做项目级自定义。
易协作实例易协作 业务方维度的隔离单元（如 H72、大话西游）。实例是可见性判定的基本单位。
易协作项目易协作 实例下的协作单元，是用户使用 Agent 的业务上下文。
成员易协作 项目下的用户，带角色属性：管理员 / 普通成员，是操作权限判定的依据。

3.2 关系模型

关系基数说明

3.3 分类与展示标签

维度选择方式字典归属业务含义
分类单选租户字典
（Agent 与模板共用）		 业务领域归类，用于列表检索与统计，不参与权限判定
展示标签多选官方字典 承载实例标识（如 H72、大话西游），是 Agenthub 判定可见范围的核心依据。同时用系统标记区分母版 / 实例模板
  • 母版与实例模板的分类由母版决定，实例模板不可单独修改。
  • 展示标签中的母版、实例模板为系统标记，由派生逻辑自动写入，不可人工增删。
  • 实例标签在实例模板派生时由易协作传入的实例信息自动写入，并随实例 Agent 一起带出。
  • 字典的增删改由租户在「管理分类 / 管理标签」中维护；删除字典项时，引用该项的对象自动解除引用。

04核心业务流程

4.1 初始化链路：存量实例批量接入

1
创建母版租户管理员
在 Studio 租户后台「Agent 管理 → 模板」创建 PM Agent 母版，配置名称、描述、系统提示词、模型、内置工具、Skills、MCP（含 brainmaker 知识库），并设置分类。
2
批量创建实例模板易协作系统
易协作遍历全部存量实例，调用 Studio「创建实例模板」接口，传入母版标识与实例信息。Studio 按实例逐个派生实例模板，写入实例展示标签，配置全部继承母版。
3
生成实例 Agent易协作系统
实例模板创建成功后，易协作以返回的实例模板标识调用「生成 Agent」接口，按 1:1 生成实例 Agent，Agent 归属 Studio 租户，自动带入实例模板的分类与展示标签。
4
同步关系数据易协作系统
易协作同步该实例下的「项目」与「成员（含角色）」关系至 Studio。关系数据仅落库存储，暂不在 Studio 界面展示。
5
上架 Agenthub租户管理员
在模板列表或 Agent 列表中执行上架，使其对 Agenthub 可查询。上架为可查询语义，不做数据推送。
6
初始化项目 AgentAgenthub
Agenthub 基于已上架的实例 Agent 初始化项目 Agent，用户即可开始使用。

4.2 增量链路：新实例自动接入

1
实例新建事件易协作
易协作工单平台新增实例，触发对接事件。
2
Webhook 调用 Studio易协作系统
易协作通过 Studio 提供的 Webhook 自动调用「创建实例模板」，链路与初始化完全一致，无需人工介入。
3
生成实例 Agent 并同步关系易协作系统
同 4.1 步骤 3、4。上架状态默认为未上架，由租户管理员确认后上架。
初始化与增量走同一套接口，差异仅在于触发方式：初始化为易协作侧批量遍历发起，增量为实例创建事件驱动。Studio 不区分两种来源。

4.3 母版变更链路：配置强联动下发

1
母版配置变更租户管理员
修改母版的描述、系统提示词、模型、内置工具、Skills、MCP 或分类并保存。
2
变更影响提示Studio
保存前提示本次变更将同步至 N 个实例模板与 N 个实例 Agent，需管理员确认。
3
全链路同步Studio
同步覆盖全部实例模板与实例 Agent 的对应配置项；各自的展示标签（实例标识）保持不变。同步结果写入变更记录，支持审计。
覆盖策略：母版为唯一配置真源。项目管理员在 Agenthub 侧对项目 Agent 所做的自定义配置，在母版下发时会被覆盖。Agenthub 需在管理员编辑入口明确提示该风险。字段级冲突保护策略见第 13 节待确认问题。

4.4 用户使用链路

1
用户进入 Agenthub项目成员
Agenthub 携带用户身份向 Studio 查询该用户所属的实例与角色。
2
可见性判定Agenthub
以「展示标签 = 实例」为条件，筛选出用户归属实例下、且已上架的 Agent 与模板。
3
操作权限判定Agenthub
普通成员仅可使用；实例下管理员既可使用也可管理与配置。
4
使用或自建业务 PM
直接使用已上架 Agent；或引用已上架模板自建 Agent，新建的 Agent 归属易协作租户，在 Studio 的 Agent 管理下可见可审计。

06开放能力

Studio 面向易协作与 Agenthub 提供以下能力，均以系统身份鉴权调用。此处描述业务语义，接口协议细节由技术方案定义。

能力调用方业务语义
创建实例模板易协作系统 输入母版标识 + 实例信息（实例标识、实例名称）。Studio 按实例派生实例模板，写入实例展示标签，配置继承母版，返回实例模板标识。同一实例重复调用应幂等，返回已存在的实例模板。

07权限与可见性规则

7.1 判定模型

Agenthub 侧的权限由两个维度共同决定，两者均来自 Studio 记录的「实例—项目—成员」关系：

维度一 · 归属
用户是否归属于该 Agent 的展示标签所标识的实例 → 决定能否看见
维度二 · 角色
用户在该实例下是否为管理员 → 决定能否管理与配置

7.2 权限矩阵

用户与该实例的关系可见可使用可管理 / 配置说明
不归属该实例否否否展示标签不匹配，查询结果中不返回
归属该实例 · 普通成员是是否只能用，不能改
归属该实例 · 管理员是是是可管理与配置项目 Agent

7.3 前置条件

  • 上述判定的前提是该模板 / Agent 处于已上架状态；未上架对象对所有 Agenthub 用户均不可见。
  • 分类不参与权限判定，仅用于检索与统计。
  • Studio 租户后台的管理权限沿用现有租户权限体系，不受本规则影响。

13待确认问题

Q1 · Agenthub 管理员的项目级自定义与母版强联动如何共存？
当前结论为母版覆盖优先。但图示中 Agenthub 具备"项目管理员管理和修改项目 Agent，实现项目自定义配置"的能力，两者存在冲突。建议：定义字段级策略——提示词、模型、工具、Skills、MCP 由母版强管控；项目 Agent 的名称、欢迎语等展示层字段允许项目自治且不被覆盖。需与 Agenthub 侧对齐。
Q2 · 一个易协作实例是否可能对应多个母版？
当前按"实例模板与实例 1:1"设计。若未来同一实例需要多种角色的 Agent（如 PM 助理 + 测试助理），则实例与实例模板将变为 1:n，需在派生时增加母版维度的唯一性约束。需确认是否纳入本期设计。
Q3 · 项目维度是否需要进入 Agent 归属链路？
本期实例 Agent 按实例 1:1 生成，项目仅作为关系数据存储。若后续需要项目级的差异化配置或用量统计，需明确项目 Agent 与实例 Agent 的对应关系及其数据归属。
Q4 · 关系数据的同步时效与触发方式？
成员变动直接影响可见性。需确认是实时事件同步还是定时全量同步，以及可接受的延迟上限。
Q5 · 存量超管模板的迁移方案？
超管后台模版管理下线后，已有模板及其派生的 Agent 如何迁移到租户后台，是否需要数据迁移脚本与灰度期并行。
